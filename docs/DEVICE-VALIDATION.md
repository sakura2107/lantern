# Android 真机与新网络复测

日期：2026-10-13，Asia/Tokyo。所有数字标为**实测**；这是有限测试，不是完整产品验收。

## 设备与链路

- 一加 Ace 5 Pro，设备型号 PKR110；Android 16 / API 36；ARM64；系统 SoC 属性 SM8750。
- Windows 主机：i5-14600KF、RTX 4070 SUPER；本文件早期网络对比使用 GDI/WIC 软件 JPEG。后续硬件桌面见 HARDWARE-DESKTOP.md。
- 旧局域网：主机 192.168.31.58、手机 192.168.31.137。
- 新局域网：主机 WLAN 10.217.43.110、手机 wlan2 10.217.43.250；Windows 默认网关也为手机地址，符合手机热点连接拓扑。
- USB 仅用于安装、调试、日志和内存中的配对资料传递。远程文件和 JPEG 使用真实无线局域网 TCP 47443，没有用 USB 转发替代性能测量。
- 配对资料通过 debug-only instrumentation 的本地 socket 传递，只接受 root/adb shell UID；不放到命令行或结果日志。凭据最终由 Android Keystore AES-GCM 保存。

## 已通过的检查

最初的新旧网络各完成 48 个断言：18 个基础检查与 30 次 JPEG 解码检查，包括真实 TLS/指纹认证、独立文件页、读取权限与写入拒绝、32 MiB 文件的取消/续传/哈希、双向恢复、原始文件代理 FD 随机 seek/read、只读拒绝、缓存 content URI、Keystore、真实界面配对/文件页/画面显示，以及隐藏显示与停止订阅的区别。

源码测试入口：`android/app/src/debug/java/org/lantern/client/DeviceTestRunner.java`；调度脚本：`tests/device_debug.py`。Instrumentation 只进入调试构建，不是生产权限入口。它不把诊断步骤宣称成完整媒体播放器或控制界面功能。

初次没有前台活动的 instrumentation 在恢复下载中出现 connection abort；改为在测试期间显示本应用，并仅对测试窗口保持亮屏后完整通过。这个结果提示后台/休眠测试必须单独开展，不能宣称后台持续传输已通过。常规应用不永久修改手机屏幕超时。

## 新旧网络对比

两个对比文件 `device-lan-old-network.json` 与 `device-lan-before-pacing.json` 使用相同版本代码、32 MiB 确定性文件和相同请求参数。

| 指标（实测） | 旧网络 | 新网络 |
|---|---:|---:|
| TLS + 授权单次耗时 | 62.81 ms | 35.44 ms |
| 32 MiB 完整下载，含源/本地 hash、每块刷新及提交 | 10.866 s | 3.205 s |
| 完整下载有效吞吐 | 2.95 MiB/s | 9.98 MiB/s |
| 下载取消后的确认恢复位置 | 1 MiB | 1 MiB |
| 恢复下载剩余 31 MiB，含校验 | 9.288 s | 2.205 s |
| 上传取消后的确认恢复位置 | 1 MiB | 1 MiB |
| 恢复上传剩余 31 MiB，含 hash 与主机提交 | 9.136 s | 3.006 s |
| 恢复上传有效吞吐 | 3.39 MiB/s | 10.31 MiB/s |
| 1280 宽 JPEG，30 次采集/TLS/Bitmap 解码请求吞吐 | 10.72 fps | 15.06 fps |
| 同一请求耗时 p50 / p95 | 91.29 / 109.60 ms | 67.65 / 77.80 ms |
| 30 帧 JPEG 总字节 | 3,049,513 | 2,568,991 |

当前 bulk 固定持续预算是 10 MiB/s，并允许积累最多 10 MiB burst。恢复时可使用已有令牌，所以恢复下载短时约 14.06 MiB/s 不能当作持续上限；新网络的完整下载已接近软件持续限速，不能据此推断链路最大带宽。单独的完整上传吞吐还未记录，上表是恢复上传。

桌面内容会变化，两个样本的 JPEG 字节量不同；因此 fps 变化是这两次工作桌面的观察，不是严格相同像素序列的 A/B 基准。计时包含请求、主机采集/编码、网络和 Android Bitmap 解码，**不包括输入事件至屏幕呈现的光学端到端延迟**。也没有测硬件解码、视频音轨或字幕。

## 桌面调度修正：真实界面更新率

旧代码 `scheduleWithFixedDelay(..., 100 ms)` 每次请求、解码后额外等待 100 ms；Windows 也在每轮结束后等待 83 ms。原先 15.06 fps 是快速请求/解码吞吐，不能当作旧版实际界面帧率。

本次使用同一台手机、同一无线网络、1280 宽/JPEG 质量 65，测量 10 秒内唯一新 Bitmap 的 `ImageView.onDraw`，测量窗口没有第二条桌面测试连接或文件传输。旧版本只增加相同的绘制计数和角标，没有改变 100 ms 调度；修正版计入处理耗时，以最高 30 fps 周期预算调度，超期不等待、不积压。

| 实测指标 | 修正前 | 修正后 |
|---|---:|---:|
| 10 秒新画面绘制次数 | 57 | 151 |
| 界面画面更新率 | 5.70 fps | 15.10 fps |
| 新画面绘制间隔 p50 | 166.74 ms | 66.61 ms |
| 新画面绘制间隔 p95 | 183.58 ms | 83.62 ms |

证据：`desktop-before-pacing.json`、`device-lan-after-pacing.json`。修正后完整真机回归 49 项通过（原 48 项加独立绘制计数）。这是约 2.65 倍的本次观察，桌面内容未固定为同一像素序列，不当作严格编码性能基准，也不当作稳定最低帧率承诺。`onDraw` 不是 GPU fence、面板实际发光或输入光学端到端测量。

两端仍使用 GDI/WIC 软件 JPEG、可靠 TLS/TCP 单帧 pull。JPEG 已做有损图像压缩，但没有帧间压缩、硬件编码、零复制 GPU 管线、自动码率反馈或可丢弃过期网络包；15 fps 仍未达到 1080p60 目标。原始电影字节走独立范围读取，不通过此画面管线，也不重复压缩 MP4/MKV。

安卓新增“画质”三档、绘制 fps 角标和边缘点击坐标上限。Windows 相同调度修正已构建并通过 core、integration、java_interop；Windows 连接态显示帧率尚未单独实测。

### 三档画质复测

单独桌面验证 `desktop-profiles.json` 有 41 项通过，其中均衡档 10 秒，快速与清晰档各 5 秒；每次切换等待 500 ms 后开始计数。

| 档位 | 请求宽度 / JPEG 质量 | 实测绘制更新率 | 绘制间隔 p95 |
|---|---:|---:|---:|
| 快速 | 960 / 55 | 18.00 fps | 67.11 ms |
| 均衡 | 1280 / 65 | 15.20 fps | 84.01 ms |
| 清晰 | 1920 / 75 | 11.00 fps | 101.50 ms |

快速和清晰档实际解码宽度分别为 960、1920；画质弹窗的三个选项也在真实 UI 中确认可见。首版由用户手动选择，尚无自适应码率。短窗口、工作桌面、内容变化均限制结果的代表性；不据此承诺运动视频或持续最低帧率。安装后重新连接并订阅桌面，截图角标显示 JPEG 1280×720 / 15.3 fps，仍是有限瞬时观察。

复测命令在已授权真机上执行（输入 SDK 路径；共享目录只包含生成数据）：

```powershell
python tests/device_debug.py --adb C:/tools/platform-tools/adb.exe --serial DEVICE_SERIAL --host-exe package/lantern.exe --apk ../Lantern-0.1-Android-debug.apk --address HOST_LAN_IP --work C:/LanternTests --report desktop-profiles.json --desktop-only --keep-host
```

不要同时运行两个同端口测试；省略 `--desktop-only` 执行文件续传、权限和桌面完整测试。临时复制主机 EXE 后的首次连接曾因新路径防火墙阻止而超时；切回已有允许规则的 package/lantern.exe 后通过，没有修改防火墙权限。测试留下的 Windows 防火墙弹窗可以关闭，不需要允许 lantern-before.exe。

## 运行与界面检查

安装后系统 `am start -W` 曾报告冷活动启动 332 ms；后续进程重启报告约 182–185 ms。这是 Android 框架启动耗时，缓存/预热条件未统一，不作为严格冷缓存启动基准。

本次文件页连接状态已确认，手机仍可使用测试主机 `10.217.43.110:47443`。只授权工作目录下专门生成的测试文件；没有共享用户个人文件。测试主机 PID 和状态目录记录在 `work/device-debug/phone-41f53c56/host-process.json`，这些是本次工作目录记录，不是发布配置。网络或进程再次变化时需要重新连接。

一次连接后的手机内存采样：PSS 104,359 KiB、RSS 226,756 KiB（不是长稳峰值），明显高于原先 40 MiB 空闲目标，尚未优化。电池温度属性当时为 361，即 36.1°C；USB 充电开启。这仅是一时读数，**不能归因于本软件或当作热稳定性结论**。

真机中已修正 JPEG 显示为保持比例、只在订阅时占用画面区域、按图像矩阵映射触控并忽略黑边，以及浅色界面的状态栏图标。协议发送已合并长度头和初始内容，Android 每次完整 RPC 统一刷新有界缓冲，减少细碎 TLS 写入；旧网络复测并未证明总体稳定提速，不把此改动效果与换网络混淆。
