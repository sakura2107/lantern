# Windows 界面重写（客户端与主机管理）

本轮重写了 `lantern-client.exe`（`src/gui.cpp`）和 `lantern-host.exe`（`src/host_gui.cpp`）的表现层，设计语言与 Android 端一致。协议、权限、凭据、文件任务、线程与关闭顺序没有改动。

## 设计

- **共享组件** `src/ui_kit.hpp`（仅头文件，无新依赖）：
  - **设计令牌**：与 Android `Theme.java` 相同。冷灰底色，主操作用墨色，琥珀色“灯”只表示正在进行（已验证、画面开启、主机运行）。
  - **深浅色**：跟随 Windows 设置；切换系统主题时即时刷新。
  - **按 DPI 缩放**：所有尺寸经 `dp()` 换算，支持每显示器 DPI（`WM_DPICHANGED`），不再依赖固定像素布局。
  - **自绘按钮**：主要、次要、幽灵、危险、导航、开关卡片、勾选标签。悬停、按下、禁用、键盘焦点环都有对应状态。
  - **布局**：卡片、输入框外框（获得焦点时琥珀描边）和流式布局。窗口变窄时按钮换行，不会被截断。
  - **输入对话框** `ui::prompt`：用于新建文件夹、重命名、移动、复制、另存。
  - 绘制使用 GDI+（Windows 自带，无需部署）。暗色菜单和滚动条使用 uxtheme 的未公开序号函数；系统缺少时会自动跳过。
- **应用图标**：`assets/lantern.ico` 包含 16–256 px 共 10 个 PNG 尺寸，母版是 `assets/lantern-icon.svg`。
  - **资源**：`src/app_icon.rc` 以资源 ID 1（`LANTERN_APP_ICON`，见 `src/app_icon.h`）编进 `lantern.exe`、`lantern-host.exe` 和 `lantern-client.exe`，资源管理器据此显示 exe 图标。主机管理的向导对话框资源 101 不受影响。
  - **窗口图标**：`ui::class_icons` 在注册窗口类时，按系统 DPI 设置大、小图标。`ui::window_icons` 在建窗后和 `WM_DPICHANGED` 时，按窗口所在显示器的 DPI 重新设置标题栏和任务栏图标。
  - **加载方式**：都用 `LoadIconWithScaleDown` 从更大的尺寸缩小，不会出现放大造成的模糊。
- **视频不受影响**：桌面画面仍走 D3D/Media Foundation 交换链。界面层只在没有画面时绘制空状态（未开启 / 已隐藏 / 连接中），没有增加任何 CPU 回读。

## 客户端结构

左侧导航栏：设备 / 桌面 / 文件 / 传输，底部是“管理本机主机”和连接状态卡（未配对、已保存、正在验证、已验证、验证失败；有画面或声音时附带说明）。快捷键：Ctrl+1…4 切换页面，文件页 F5 刷新，F11 全屏，Esc 退出全屏。远程桌面获得焦点时，这些按键会照常发送给电脑。

| 页面 | 内容 |
|---|---|
| 设备 | 地址、证书指纹、配对密钥、验证并保存、局域网发现、用配对链接连接（ID 121）、网络诊断；“权限与隐私”说明 |
| 桌面 | 四个互相独立的开关卡片：画面 / 隐藏本机画面 / 控制 / 声音；画质、显示器、时序、缩放复位；底部是文字输入、快捷键和剪贴板 |
| 文件 | 上级、刷新、路径、排序；搜索框、筛选本页、搜索子文件夹；上传文件、上传文件夹；下载、打开、打开方式、更多；列表加预览卡；原始媒体直读开启后才出现播放器栏 |
| 传输 | 暂停、继续、移除、另存为、打开；优先级、速度上限、应用；任务列表 |

- **全屏**：顶部是深色工具条（四个开关、画质、显示器、时序、缩放、返回文件、退出全屏）。可以收起成一个小把手，点一下即可再次展开。
- **“更多”菜单与右键菜单**：新建文件夹、重命名、移动到、在电脑上复制、文件信息与 SHA-256、原始媒体直读、取消当前文件操作、删除。删除的确认框写明“在电脑上永久删除”，默认焦点在“否”。
- **空列表**：显示下一步该做什么（先去“设备”页验证、输入目录后刷新、去“文件”页上传或下载）。

## 主机管理结构

左侧导航栏：主机设置 / 设备与权限 / 当前连接，底部状态卡显示主机状态和连接数。

- **主机设置**：状态目录（浏览、加载、新建主机配置）；授权目录与证书指纹两行，旁边是“更改授权目录…”（ID 38）；全局权限上限（勾选标签）；监听地址、端口、共享带宽，启动 / 停止。
  - **更改授权目录**：调用 `HostAdministration::root()`，只改授权目录，证书指纹、设备和密钥保持不变。校验与新建主机时相同：必须是已存在且不是重解析点的目录，身份状态不能位于其中。主机运行时不可用；有回归测试（`tests/host_admin.cpp`）。
  - **新建主机配置**：如果状态目录已存在，会自动换到新的目录，并在确认框中提醒“这会创建新主机，需重新配对”。原来的行为是静默报错并保留旧配置。创建或更改失败时会弹窗说明原因。
  - **两个“浏览”按钮**：都从输入框里已填写的目录开始，不再停在系统上次的位置。
  - **记住上次的配置**：
    - **保存内容**：加载成功、启动主机、应用带宽和关闭窗口时，把状态目录、监听地址、端口和共享带宽写入 `%LOCALAPPDATA%\Lantern\host-manager.ini`。文件里不含密钥，写入采用先写临时文件再替换的方式。
    - **下次启动**：自动填回这些值，并加载上次的状态目录。不会自动启动监听。
    - **目录已被删除时**：状态栏会说明，不会静默恢复成空白。
    - **测试**：环境变量 `LANTERN_HOST_MANAGER_SETTINGS` 可改用其他文件，设为空则不读也不写。`windows_ui_smoke.ps1`、`setup_gui.py` 和 `host_admin_gui.py` 都使用各自的临时文件，不会改动使用者的设置。
  - **扫码添加设备**（后端接口见 [PAIRING-BACKEND-HANDOFF.md](PAIRING-BACKEND-HANDOFF.md)）：
    - **入口**：“设备与权限”页的“扫码添加”（ID 60），以及主机设置页启动、停止按钮旁的“扫码添加设备”（ID 62）。两个入口打开同一个非模态窗口（类名 `LanternPairing`），同一时间只有一个。
    - **二维码**：
      - 主机运行并监听局域网地址时，在后台线程生成一次性邀请、链接和二维码。
      - 绘制时四周留出 4 个模块的空白，每个模块使用整数像素，无平滑；深色模式下仍是白底黑码。
      - 下方显示倒计时、主机名和地址。地址规则：绑定具体 IP 时只用这个 IP；绑定 `0.0.0.0` 时，物理网卡排在前面，最多 8 个；只有找不到物理网卡时才使用虚拟网卡；绝不编码 `0.0.0.0`。
    - **权限**：默认勾选主机上限内除“文件写入”以外的全部权限，上限外的项目不可选。改动任一项会作废旧邀请并生成新的。
    - **完成检测**：每 2 秒检查一次邀请是否还在待用列表里。邀请消失且未过期，就视为已被使用：二维码被清除，窗口显示新设备的名称，并刷新设备列表。过期后，二维码变灰并显示“已过期”。
    - **未就绪时**：没有配置、主机未启动或只监听本机时，窗口会说明原因。后两种情况提供“改为局域网并启动主机”，它会把地址改为 `0.0.0.0` 并启动主机。
    - **安全**：
      - 配对码和链接只保存在窗口内存里。关闭窗口时取消未使用的邀请，并清空链接和二维码。
      - “复制链接”只在用户点击时写入剪贴板，链接同样只能使用一次。
      - 配对码和链接不会写入日志、设置文件或错误提示。
  - **局域网默认值与防火墙**：
    - **默认地址**：首次运行和新建主机配置时，监听地址默认为 `0.0.0.0`（`default_host_bind`）。已记住的地址，包括 `127.0.0.1`，保持不变。
    - **地址说明行**：“网络与运行”标题下的说明会随输入实时更新，显示手机可用的地址和防火墙状态；只监听本机时会提示改为 `0.0.0.0`。
    - **防火墙检测**：启动时、启动主机后，都会在后台查询“专用网络”规则（`firewall_state`）。
    - **“允许通过防火墙”按钮（ID 63）**：只在规则未确认放行时显示。点击后在后台调用 `request_firewall_allow(lantern-host.exe, 端口)`，弹出 UAC，只为专用网络添加规则。拒绝授权时，状态栏会说明，并提示可以手动放行。
  - **驱动器根目录**：`E:\` 这类根目录可以直接授权。
    - **原缺陷**：排序分页列表（Op 44，手机端和 Windows 客户端都用它）会逐个打开子文件夹读取元数据。驱动器根里的 `System Volume Information` 普通账户无权打开，整页因此报 `Open authorized path (Windows 5)`，手机端显示为“空文件夹”。
    - **修复**：打不开的子文件夹直接跳过；同时带隐藏和系统属性的项目在列表和搜索中都不显示，与资源管理器默认一致。回归测试见 `tests/integration.cpp` 的 `unopenable_children`。已在真机上确认可以浏览 `E:\`。
  - **结束会话（协议 `session=end-v1`）**：
    - **原问题**：“结束设备全部会话”和“终止选中的连接”确实会关闭连接，但设备信任保留，手机会立即自动重连，看起来像没生效。
    - **现在**：管理员结束会话后，主机会记录该设备的一个“已结束”标记，最长 10 分钟。在此期间，带“自动重连”标志的握手会被拒绝，错误码 `cancelled`，提示“电脑已结束此设备的连接”。
    - **主动连接不受影响**：不带标志的主动连接（手机上点“连接电脑”）照常成功，并清除该标记。
    - **兼容性**：标志放在 HELLO 末尾的可选字段里，只有主机在能力串中声明 `session=end-v1` 时客户端才会发送，所以旧客户端和旧主机的行为不变。
    - **测试**：见 `tests/host_admin.cpp`，覆盖自动重连被拒、主动重连成功并清除标记、未被结束的设备不受影响。
  - **路径分隔符**：新建主机目录原来拼成 `...\Lantern/hosts\host-…`，路径里混有 `/`，系统文件对话框会拒绝打开，导致“浏览”按钮无反应。现在统一使用 `\`，加载时也会规范化输入框里的路径。
- **设备与权限**：旧共享凭据横幅和“禁用”按钮；设备列表（显示生效权限）；新增设备；选中设备的配置权限和保存；查看配对资料、结束设备全部会话、撤销设备、刷新；配对密钥默认遮罩，勾选“显示配对密钥”才显示。
- **当前连接**：说明、连接列表、终止选中的连接。
