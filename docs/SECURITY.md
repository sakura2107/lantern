# 安全模型与首版限制

## 一次性扫码配对与局域网后端

当前新增邀请式配对，接口和前端注意事项见 [PAIRING-BACKEND-HANDOFF.md](PAIRING-BACKEND-HANDOFF.md)。以下历史首版描述中的共享密钥、默认回环和缺少逐设备管理等限制，应以当前实现和本节为准。

邀请默认 10 分钟，可明确指定 1 秒至 24 小时；最多 32 个待配对邀请。码由随机 128-bit 公开定位 ID 和独立随机 128-bit 秘密组成，两部分来自 Windows CNG 的现有 `random_token()`。攻击者知道 ID 时，秘密仍有 128-bit 熵。配置只保存完整码的 SHA-256，哈希比较使用固定长度逐字节累积，码和秘密不落盘；DPAPI 另外保护邀请元数据与正式设备凭据。明文只在生成返回值、二维码以及客户端兑换所需的短暂内存中存在。调用方不要记录或缓存二维码 URI。

同邀请 5 个错误秘密后删除。每来源 IP 使用滑动 60 秒、最多 10 个 PAIR 请求的限速，表有 1024 来源上限，满表拒绝新来源。未知 ID 不会增加其他邀请的失败次数。网络只在 TLS 完成且完整证书指纹固定通过后提交码；配置锁下原子执行“验证邀请、创建独立随机设备令牌、移除邀请”，并使用原有原子 DPAPI 提交。并发扫描只允许一个成功。取消/过期/重复使用使用同一 unauthorized 提示。邀请清理是访问时清理，不需要后台定时器；过期验证始终生效。

已有 HELLO、逐设备权限、撤销与会话结束逻辑保持原有行为。配对权限不会超过邀请或兑换时的主机全局上限。响应丢失可能已经创建设备而客户端没有拿到令牌，因此不自动重放兑换；用户应检查电脑设备列表，删除多余条目，再生成新邀请。TLS 握手和单帧本身仍受既有资源与超时上限约束；PAIR 限速不是完整的握手抗 DoS，重启或另一个 Host 进程有独立 IP 表。

Host 构造和 CLI 的默认绑定改为 `0.0.0.0:47443`；这会监听所有 IPv4 接口。身份创建不会自动启动主机，也不会自动请求提权。前端已有的显式或持久化回环设置不会被后端覆盖，前端应显式接入新默认值。扫码不经 UDP 发现获得信任，二维码必须来自用户认可的电脑屏幕。

防火墙辅助只由明确调用的 CLI / `request_firewall_allow` 执行，添加或更新两条确定名称的入站规则：`Lantern 主机`（目标程序 + 指定 TCP 端口）和 `Lantern 主机（发现）`（同一目标程序 + UDP47442）。仅 `NET_FW_PROFILE2_PRIVATE`，来源限本地子网，关闭 edge traversal；不启用 Public/Domain，不关闭防火墙，不修改当前网络类别。使用专用网络是因为家庭可信 LAN 可由用户认可，公共 Wi-Fi 上不应暴露远程文件/控制入口。

只读 `firewall_state` 是 Private-profile TCP 策略检查，显式 block 优先；遇到服务/接口/地址限制、组策略覆盖或 COM 失败时保守返回 unknown。它不证明当前 Wi-Fi 的网络类别、路由可达性、第三方防火墙或 UDP 发现可用；规则添加成功也不等于网络连通已验证。UAC 拒绝、工具缺失、子进程失败或超时返回 false，前端应保留手动操作入口。

主机配置写入 v3 并兼容读取 v1/v2；不允许旧版主机/管理程序在升级后的配置上混用。新依赖 Nayuki QR Code generator 仅负责编码，静态编入；不加入扫描库、外部服务或新的网络依赖。

## 已实施

- 随机 256-bit 配对密钥，TLS 1.2；客户端必须事先核对完整证书 SHA256 指纹。指纹失败发生在发送密钥前。Windows 使用系统 Schannel，Android 的 TrustManager 校验固定证书与有效期；不会自动信任任意自签名证书。
- Windows 主机配置、PFX 私钥和本机 CLI 密钥使用当前用户 DPAPI；Android 密钥由 Android Keystore AES-GCM 包装，不写明文偏好或日志。GUI 的 Windows 配对密钥暂存在内存中，没有自动保存。
- 读、写、观看、控制、系统音频分别请求与检查；音频只能在显式audio=16配置后成功，已有15配置不扩大授权。仅身份配对请求0，不赋予任何业务权限。默认只读示例、默认回环监听。启动主机是用户明确操作，没有无人值守自动安装。
- 每条普通请求复查密钥和当前权限，H264 持续流每 250 ms 复查观看权限；revoke 轮换主机级密钥。主机结束时 shutdown 所有 socket。握手/读写有 15 s 超时、帧和字段有上限、固定工作线程与待处理连接上限。
- 相对路径拒绝 `..`、绝对路径、驱动器、ADS、反斜杠、空组件、尾部点/空格、设备名称及内部暂存命名空间；Windows UTF-8 转换严格拒绝非法序列。
- 授权根目录和逐级目录持有实际句柄；拒绝 reparse point（包括 junction、符号链接）、拒绝多硬链接普通文件；父目录禁止 delete sharing，以限制替换逃逸。删除/移动使用句柄并复核源文件身份，避免仅验证字符串后按路径删除。
- 暂存与最终文件分离，完成整文件哈希后才提交。目标竞争不覆盖。损坏、空间不足、占用、源变化分别失败并保留恢复资料。
- Android provider 不导出，仅允许临时 URI 权限；只接受 `r` 模式、只共享注册条目。使用 `content://`、ClipData 和 `FLAG_GRANT_READ_URI_PERMISSION`，不使用 file URI。参考 Android [安全文件共享](https://developer.android.com/training/secure-file-sharing/share-file)。
- 本机 HTTP 媒体桥只监听 loopback，随机路径令牌；每个 HTTP 请求上限 8 KiB 头部，分块和消费者数量有上限。它的 URL 也是访问能力，不能发到日志或公共网页。

## 公网连接后端（2026-10-16）

本节覆盖下方早期原型的公网限制描述。公网入口默认不广告，也不自动改动 Windows 或路由器策略。启用公网要求先禁用旧共享凭据，保留每台设备的独立随机令牌和权限。TLS 1.2、完整证书指纹和有效期验证不因地址、域名或路径切换而放宽；已发现的 pin mismatch 直接终止竞争，不在另一地址上发送凭据。认证前不下发公网入口，发现协议不增加地址信息。

启用公网时，威胁包括慢 TLS/首帧、来源轮换、撞令牌、扫描端口和路由器恶意响应。接纳至第一条 HELLO 完成的总预算为约 10 秒，首帧限制 512 字节。主机为连接分配受限的独立处理线程，未认证连接最多 32、每来源最多 4；IPv4 使用单地址，IPv6 按 /64 聚合。认证后的会话有独立的 16 个名额，慢连接不占这些名额；总活动连接另有 64 的硬上限。源表上限 1024，闲置记录 5 分钟后清理。来自足够多不同网络的攻击仍可能占满未认证接纳容量，本实现不承诺抵抗大规模分布式 DoS。

HELLO 凭据或权限校验失败会按来源增加退避：250 ms、500 ms、1 s 等，最高 60 s；退避期间返回 busy，不占线程睡眠。成功 HELLO 清除该来源的失败记录。来源限额不把一个 IPv6 前缀中的临时地址当作新设备。拒绝、限速和超时计数及最近 32 条脱敏事件只供本机管理，记录来源聚合键、时间和错误码，不记录密钥、配对码、设备名或请求内容。LAN 模式保留原有凭据/授权逻辑，不启用公网专用的来源限额和失败退避。

一次性邀请默认只允许本地来源兑换，是为了降低二维码被拍摄/转发后在外网盗用的风险。只有明确选择 `allow_remote` 的邀请才允许外网兑换；熵、哈希、常量时间比较、10 分钟默认 TTL、单次原子消费和 5 次失败作废保持不变。不能把已生成的邀请码当作可恢复的账号密码。

公网防火墙规则名为“Lantern 主机（公网）”，绑定程序、入站 TCP 和指定监听端口、RemoteAddresses=`*`，**只作用于 Private 配置文件**，不放行 UDP、不打开 Edge Traversal。LAN 规则仍是 Private + LocalSubnet。理由是公网入口应只在用户信任的家庭网络中运行；连接到酒店等公用网络时不应隐式暴露。若 Windows 当前分类为 Public，前端须提示规则在该网络不生效，并引导用户自行确认网络是否可信；不得自动改网络类别或加入 Public 配置文件。规则增删仅由用户按钮调用 runas CLI；关闭公网后界面应显式请求删除公网规则。

UPnP 仅在用户请求 map 后向 LAN 发 SSDP 和 SOAP，使用有租期的 TCP 映射/IPv6 pinhole，运行中续期，正常停止时删除；进程崩溃时依靠租期兜底。拒绝外部 SSDP 目标、非数字或非本地控制地址、与 SSDP 响应来源不同的 HTTP 主机、HTTP 重定向、代理、自动认证和 XML DTD。响应有长度/深度上限。网关是未认证的 LAN 设备，恶意 LAN 设备仍可能伪造发现；路由器返回成功只能证明操作被受理。CGNAT/私有 WAN 地址不被误报为公网 IPv4，也不会尝试访问外部“查 IP”站点。

地址枚举、Windows 策略和 UPnP 状态只能描述本机侧准备情况，不能证明运营商、家庭路由器或手机网络允许入站。客户端诊断仅访问配置入口，提供 TCP/TLS 阶段和认证后 ping 延迟。没有 STUN、TURN、中继、PCP/NAT-PMP 或自动 DDNS 更新；DDNS 域名由用户在外部维护。本次没有新增第三方网络库。

## 不能宣称的保证

本版未经独立安全审计。公网接纳限制不能替代路由器/系统的防洪能力，不能抵抗充分分布式 DoS。设备发现仍不提供身份认证；没有客户端公钥身份、完整凭据到期策略或无人值守系统服务。

配对由指纹固定和一次性高熵邀请完成，不是短码 PAKE。每台设备有独立随机令牌，可单独撤销。密钥丢失后应撤销该设备并重新配对；软件不把凭据发给第三方。

状态目录应在授权根之外并使用用户私有 ACL。DPAPI 无法防御已控制同一 Windows 用户会话的恶意程序。本实现不是对抗已拥有主机同用户权限的沙箱；本地恶意程序可以读进程内存、截取键盘或篡改文件。NTFS 文件 ID/mtime 可检测普通源修改，不承诺抵御本地恶意程序刻意恢复修改时间的场景。

Windows 应用在当前交互会话运行。不能通过 SendInput 控制高完整性、安全桌面或其他登录会话；捕获受保护视频也可能失败或黑屏。本版不提供隐私屏、虚拟显示器、物理显示器断电后保持采集，也不声称锁屏后仍可控制。

新增Android拖拽使用每连接InputSession鼠标租约，全局单个左键所有者；取消、断线、解析/授权错误释放，50ms检查线程在1800ms没有刷新后尽力释放。输入法与新式单键操作发送完整按放批次。旧op22原始按键仍无完整修饰键状态表和掉线释放；不能称所有键盘控制已完成。输入焦点只读取标准Edit/RichEdit类型与只读/密码标志，不读取文本内容。产品不记录键盘文字；测试生成窗口的专用记录仅用于核对生成测试字符。

缓存管理仍有限：Windows 文档打开缓存放用户临时目录下，单文件最多 512 MiB、总体最多 2 GiB；普通下载到用户指定位置不受此缓存配额限制。Android 下载保存在应用私有 files/received，总量限制 16 GiB、保留 64 MiB 空间。尚无完整 LRU/容量配置/活动共享回收。Android 上传快照另限制 16 GiB，并保留 64 MiB 磁盘空间。不要把缓存管理视为已完成；设备测试应检查存储满、应用被杀和外部应用仍持有 FD 的情况。首版不自动删除正被接收应用使用的文件；可在会话结束后清理缓存/应用数据。代理 FD 同时最多 8 个，共享 URI 映射最多 32 项。

## 公网与第三方插件的后续约束

公网默认不开启。以后可选直连/ICE/STUN/TURN/中继模块必须保持端到端身份与加密，不能因使用中继而弱化验证。中继需要服务器、流量和运维成本；一个 100 Mbps 持续观影连接约每小时 45 GB 单方向有效媒体流量，中继服务商可能按 ingress/egress 双边计费；以具体套餐为准，这不是报价。

未签名/未经审核的媒体解析器不应加载到凭据所在主进程。动态插件 ABI 只解决二进制兼容，不能提供安全隔离；高风险插件需要独立进程、资源限制和受控 IPC。当前只有受信任示例被测试加载，产品主机没有自动扫描或加载插件目录。

办公文件优先只读；没有编辑回传，所以不会把用户修改自动写回远端。以后编辑回传必须先固定原文件 version/hash，再比较并提交新临时版本；冲突另存、保留原件、重试可恢复。

硬件提供者只从 System32 加载 NVIDIA 编码驱动，验证 API 版本；不从工作目录加载同名 DLL。H264 码流有尺寸、长度、序列与时间戳界限，但未对系统 GPU/解码驱动做独立安全审计。持续 TCP 桌面最多两路；GPU 采集错误、授权撤销或积压会关闭流，不宣称安全桌面仍可控制。

Android控制开启需单独HELLO授权成功；输入队列32项、后台独立连接。op35一次完整点击消息由服务器合批注入，并尽力释放部分注入的左键。消息确认丢失不会无限重试。离开前台/切换设备取消旧输入。
