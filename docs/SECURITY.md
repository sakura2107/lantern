# 安全模型与首版限制

## 已实施

- 随机 256-bit 配对密钥，TLS 1.2；客户端必须事先核对完整证书 SHA256 指纹。指纹失败发生在发送密钥前。Windows 使用系统 Schannel，Android 的 TrustManager 校验固定证书与有效期；不会自动信任任意自签名证书。
- Windows 主机配置、PFX 私钥和本机 CLI 密钥使用当前用户 DPAPI；Android 密钥由 Android Keystore AES-GCM 包装，不写明文偏好或日志。GUI 的 Windows 配对密钥暂存在内存中，没有自动保存。
- 读、写、观看、控制、系统音频分别请求与检查；音频只能在显式audio=16配置后成功，已有15配置不扩大授权。仅身份配对请求0，不赋予任何业务权限。默认只读示例、默认回环监听。启动主机是用户明确操作，没有无人值守自动安装。
- 每条普通请求复查密钥和当前权限，H264 持续流每 250 ms 复查观看权限；revoke 轮换主机级密钥。主机结束时 shutdown 所有 socket。握手/读写有 15 s 超时、帧和字段有上限、固定工作线程与待处理连接上限。
- 相对路径拒绝 `..`、绝对路径、驱动器、ADS、反斜杠、空组件、尾部点/空格、设备名称及内部暂存命名空间；Windows UTF-8 转换严格拒绝非法序列。
- 授权根目录和逐级目录持有实际句柄；拒绝 reparse point（包括 junction、符号链接）、拒绝多硬链接普通文件；父目录禁止 delete sharing，以限制替换逃逸。删除/移动使用句柄并复核源文件身份，避免仅验证字符串后按路径删除。
- 暂存与最终文件分离，完成整文件哈希后才提交。目标竞争不覆盖。损坏、空间不足、占用、源变化分别失败并保留恢复资料。
- Android provider 不导出，仅允许临时 URI 权限；只接受 `r` 模式、只共享注册条目。使用 `content://`、ClipData 和 `FLAG_GRANT_READ_URI_PERMISSION`，不使用 file URI。参考 Android [安全文件共享](https://developer.android.com/training/secure-file-sharing/share-file)。
- 本机 HTTP 媒体桥只监听 loopback，随机路径令牌；每个 HTTP 请求上限 8 KiB 头部，分块和消费者数量有上限。它的 URL 也是访问能力，不能发到日志或公共网页。

## 不能宣称的保证

本版是实验性 LAN 原型，未经独立安全审计。不要直接暴露公网端口。没有完善的握手按源 IP 限速、防 DoS、公钥客户端身份、逐设备权限/撤销、凭据有效期、设备发现认证、用户可见会话管理或无人值守策略界面。

配对密钥由主机本地一次显示；软件不发送给第三方。首版“配对”是指纹核对加预共享随机密钥，不是短码 PAKE 流程。丢失密钥应在主机 revoke 并重新配对。所有已配对客户端共享同一主机级密钥，无法单独撤销其中一台。

状态目录应在授权根之外并使用用户私有 ACL。DPAPI 无法防御已控制同一 Windows 用户会话的恶意程序。本实现不是对抗已拥有主机同用户权限的沙箱；本地恶意程序可以读进程内存、截取键盘或篡改文件。NTFS 文件 ID/mtime 可检测普通源修改，不承诺抵御本地恶意程序刻意恢复修改时间的场景。

Windows 应用在当前交互会话运行。不能通过 SendInput 控制高完整性、安全桌面或其他登录会话；捕获受保护视频也可能失败或黑屏。本版不提供隐私屏、虚拟显示器、物理显示器断电后保持采集，也不声称锁屏后仍可控制。

新增Android拖拽使用每连接InputSession鼠标租约，全局单个左键所有者；取消、断线、解析/授权错误释放，50ms检查线程在1800ms没有刷新后尽力释放。输入法与新式单键操作发送完整按放批次。旧op22原始按键仍无完整修饰键状态表和掉线释放；不能称所有键盘控制已完成。输入焦点只读取标准Edit/RichEdit类型与只读/密码标志，不读取文本内容。产品不记录键盘文字；测试生成窗口的专用记录仅用于核对生成测试字符。

缓存管理仍有限：Windows 文档打开缓存放用户临时目录下，单文件最多 512 MiB、总体最多 2 GiB；普通下载到用户指定位置不受此缓存配额限制。Android 下载保存在应用私有 files/received，总量限制 16 GiB、保留 64 MiB 空间。尚无完整 LRU/容量配置/活动共享回收。Android 上传快照另限制 16 GiB，并保留 64 MiB 磁盘空间。不要把缓存管理视为已完成；设备测试应检查存储满、应用被杀和外部应用仍持有 FD 的情况。首版不自动删除正被接收应用使用的文件；可在会话结束后清理缓存/应用数据。代理 FD 同时最多 8 个，共享 URI 映射最多 32 项。

## 公网与第三方插件的后续约束

公网默认不开启。以后可选直连/ICE/STUN/TURN/中继模块必须保持端到端身份与加密，不能因使用中继而弱化验证。中继需要服务器、流量和运维成本；一个 100 Mbps 持续观影连接约每小时 45 GB 单方向有效媒体流量，中继服务商可能按 ingress/egress 双边计费；以具体套餐为准，这不是报价。

未签名/未经审核的媒体解析器不应加载到凭据所在主进程。动态插件 ABI 只解决二进制兼容，不能提供安全隔离；高风险插件需要独立进程、资源限制和受控 IPC。当前只有受信任示例被测试加载，产品主机没有自动扫描或加载插件目录。

办公文件优先只读；没有编辑回传，所以不会把用户修改自动写回远端。以后编辑回传必须先固定原文件 version/hash，再比较并提交新临时版本；冲突另存、保留原件、重试可恢复。

硬件提供者只从 System32 加载 NVIDIA 编码驱动，验证 API 版本；不从工作目录加载同名 DLL。H264 码流有尺寸、长度、序列与时间戳界限，但未对系统 GPU/解码驱动做独立安全审计。持续 TCP 桌面最多两路；GPU 采集错误、授权撤销或积压会关闭流，不宣称安全桌面仍可控制。

Android控制开启需单独HELLO授权成功；输入队列32项、后台独立连接。op35一次完整点击消息由服务器合批注入，并尽力释放部分注入的左键。消息确认丢失不会无限重试。离开前台/切换设备取消旧输入。
