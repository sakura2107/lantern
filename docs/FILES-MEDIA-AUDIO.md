# 文件、传输、原始影音与音频优化（2026-10-14）

文件与音频部分仍适用。后续按用户要求移除了内置视频播放器，界面改为四页，最新行为以 [UI-EXTERNAL-APPS.md](UI-EXTERNAL-APPS.md) 为准。本页内置播放数据仅作为移除前的历史实测，不能代表当前外部手机播放器的性能。完整产品仍未完成。

## 使用

配对后使用“文件管理 / 搜索 / 排序”。长按项目可重命名、主机内复制、删除、查看信息、获取 JPEG/PNG/BMP 缩略图、下载整个目录。批量选择后在文件管理中复制、移动、删除或下载选中项。复制、移动均在主机执行。删除需在应用内确认，取消删除会留下尚未删除的项目。

“传输任务”提供暂停、继续、取消、移到队首、带宽上限、已完成文件打开、缓存清理。任务记录持久化到应用私有目录；重启后未完成任务处于暂停状态，连接相同主机后继续。凭据仍只通过 Keystore 保存，不写入任务记录。新任务不覆盖同名不同内容的文件；目前冲突处理为停止并保留两端原件，没有自动改名/覆盖选项。

长按远端目录选择下载；“上传目录”使用 Android 系统目录选择器及持久读取授权。目录下载在私有暂存目录中逐文件恢复、验证，再提交完整目录。目录上传逐文件验证提交，可恢复已完成清单；远端目录会逐步出现内容，不宣称整个目录原子提交。上传使用每文件临时快照，仍存在额外本地读写；未知长度文件暂存上限 1 GiB，已知长度单文件上限 16 GiB。

点文件选择“用手机应用打开”：通过只读 content URI 按需读取原始媒体，手机系统选择器交给已有应用处理。不支持可寻址读取的接收应用可使用“下载后打开”。字幕、音轨、拖动、倍速、播放进度与连续播放由接收应用管理；本项目不再提供内置视频播放器。

“音频”优先协商 48 kHz 双声道 Opus 96 kbps，10 ms 一包。设备无 Opus 解码器、主机未编入 Opus或采样率不匹配时明确使用 PCM。旧 v1 音频客户端仍可连新主机；本次 Android 新功能请与同包主机一起升级。

## 构建与实现边界

沿用 README 中 Windows build.ps1 和 Android build-standalone.ps1。Windows 可配置 `-DLANTERN_WITH_OPUS=OFF`，此时保持 PCM 能力。Opus 通过内置 AudioEncoder 提供者接入；不暴露厂商句柄给会话层。完整 Opus 源码和许可证随源码包分发。

文件后端新增 file_queries.cpp、tree_ops.cpp、file_jobs.cpp、preview.cpp。排序分页最多扫描 200000 项，目录索引有内存限制；generation 对排序后的名称/类型/大小/时间与目录身份取摘要，拒绝跨页混用不同快照。每页仍重新扫描，并非索引数据库。搜索按小批枚举/拉取、连接关闭可取消，深度 32、扫描 200000 项上限，Android 展示最多 4096 个结果。

主机目录任务两名工作线程、排队最多 8 项、保留最多 16 项；任务进度在内存，主机重启后任务 ID 失效。复制用隐藏暂存区、拒绝链接并检查源版本；删除不具有撤销或整目录原子性。主机哈希工作可取消，结果缓存最多 256 个版本，避免反复读盘。

Android 传输最多 32 项，单传输工作线程，分块 256 KiB；新传输目录缓存上限 16 GiB、保留 64 MiB 空间。取消保留部分内容以便恢复。缓存清理只针对应用私有已完成任务。原始媒体缓存 8 × 256 KiB，共 2 MiB；随机读遇到普通 I/O 错误至多重连两次，并重新确认源版本，授权/证书/版本错误不会盲目重试。

批量流量有共享节流器：默认上限 32 MiB/s，桌面/音频期间 4 MiB/s、观影期间 2 MiB/s；独立控制连接每两秒测 RTT，相对基准增加超过 15 ms 时减半，稳定时逐渐恢复，最低 256 KiB/s，用户可进一步限速。仍为 TLS/TCP，主机保留原有有界预算调度；不是 QUIC、多客户端统一自适应拥塞控制或弱网无缝切换。

## 文件/音频实测与移除前的内置播放历史数据（不是目标或估算）

条件：OnePlus Ace 5 Pro PKR110，Android 16/API36，SM8750；Windows 主机 i5-14600KF / RTX 4070 SUPER 与手机 WLAN 同网段，USB 仅安装/调试，不传业务数据。网络未注入限速/丢包，不能将本次结果外推到公网或弱网。视频是自己生成的 12 秒 SDR 测试图案、3840×2160/30 fps、HEVC Main10、视频目标 40 Mbps、AAC，MP4约40.79 Mbps（按文件总大小/时长计算），非真实动漫、非HDR。

| 检查 | 结果 | 证据 |
|---|---|---|
| 桌面构建/单元/协议互通 | 6 个测试套件通过；新文件功能 23 项，节流器 9 项 | build/ctest 输出；tests/file_features.cpp、PacerTest.java |
| 文件/媒体安卓闭环 | MP4、MKV各22项通过，包括主机目录操作、真实暂停/续传、磁盘任务恢复、目录双向传输SHA256 | files-media-4k.json、files-media-mkv.json |
| 4K Main10 MP4 | 首帧872 ms；拖动完成1166 ms；缓冲事件0 | files-media-4k.json |
| 4K Main10 MKV | 首帧602 ms；拖动完成1439 ms；缓冲事件0；平台报告 c2.qti.hevc.decoder | files-media-mkv.json |
| 系统音频压缩 | 有效编码负载0.095996 Mbps；解码PCM约1.53594 Mbps；生成997 Hz测试音在手机实际检出 | system-audio-opus.json |
| 桌面/音频/32 MiB下载并行 | 下载9.936秒；测试稳态音频underrun增量0；音频停止11.34 ms | system-audio-opus.json |

上述媒体“首帧”来自平台渲染启动事件，“拖动”来自 seek 完成回调，不是光学延迟。MKV平台frames=306是整段测试（含拖动）的累计计数，不能除以某个等待时长当呈现帧率。短视频未报告缓冲不等于长电影流畅性验收。没有编造丢帧、温度、真实音画偏差或全天稳定性数据。

修复记录：新增测试发现目录时间戳不能可靠区分刚发生的目录变化，现使用内容摘要；空进度回调导致 bad_function_call 已修复。调试专用 DocumentsProvider 首次使用错误的 exported 属性导致测试 APK 启动失败，改为系统 MANAGE_DOCUMENTS 权限保护后通过；生产构建不包含该测试提供者。
