# Android 拖拽、电脑双击与输入法

2026-10-13，已构建并在用户的一加 Ace 5 Pro / Android 16、Windows 11 和物理 Wi-Fi LAN 上实测。完整报告 `../desktop-interaction.json`。这些能力适用于 Android 客户端，Windows GUI 当前仍是基础点击客户端。

## 用法

开启桌面订阅和控制。单击是电脑左键，双击是电脑双击，不再放大画面；单指移动直接拖拽，长按后移动也可以拖拽。可拖动窗口标题栏、选择文字，标准拖放是否接受由目标应用决定。双指保留捏合缩放与画面平移；没有开启控制时，单指仍可以平移放大的画面。

点击 Windows 标准 Edit / RichEdit 文本框后自动显示安卓输入法。未被识别的浏览器、自绘输入框、终端等，可先点电脑输入位置，再用全屏“工具 → 键盘”。返回键先收起键盘，再返回文件页。输入法候选与组合保留在手机，只有提交文字发到电脑；支持中文、英文、emoji、退格、删除、回车、Tab 与方向键。无需从电脑读取文本内容；禁用本地个性化学习和自动填充。

自动检测仅检查当前前台线程的焦点窗口类型、启用/只读/密码标志，不读取内容，不保证所有应用都能识别。安全桌面、管理员应用与完整性级别隔离仍可能拒绝 SendInput。手动键盘和输入能力不绕过这些系统限制。完整组合快捷键、选择区同步和远程 IME 状态尚未实现。

## 边界与可靠性

桌面几何仍共享 DesktopViewport；拖拽开始必须在有效画面内，移动到边缘时夹到源图像边界。一个输入工作线程拥有TLS连接；32项队列，移动合并为一个最新槽位，拖拽起止与文本保持顺序。键盘单次最多4096 UTF-16单位，拆成约256单位消息；主机每个消息最多4096 UTF-8字节/1024 UTF-16单位。输入确认丢失不重发，避免重复动作；队列溢出关闭控制并解除连接。

主机 InputSession 每条连接拥有一个鼠标租约，全局同一时刻只允许一个连接持有左键。拖拽250ms心跳，主机1800ms没有刷新租约后，由50ms检查线程尽力松开鼠标；断开、协议错误、取消也释放。其他连接的点击、键盘和旧式输入在拖拽期间被拒绝。旧协议独立按键操作仍无完整修饰键租约，不把鼠标租约称为所有键盘控制已完成。

## 实测结果

| 验证 | 结果（实测） |
|---|---|
| Android 交互断言 | 11项通过 |
| 真实窗口标题栏拖动 | 预期256,115.2；实际256,115像素 |
| Windows 双击消息 | 实际WM_LBUTTONDBLCLK已收到；手机zoom保持1 |
| 自动输入法 | 真实Android IME可见，焦点落在自定义输入连接 |
| 组合文字与退格 | Windows原生文本框最终为 `Lantern 中文 😀`，中间候选 `zhongwen` 没有传到电脑 |
| 保持拖拽 | 停在中途2100ms，心跳维持租约，继续移动并正常释放 |
| 取消、断线、心跳超时 | Windows实际鼠标状态4次按下/4次释放，无残留按住 |

文字测试向客户端InputConnection注入组合/提交回调，经真实TLS和SendInput在Windows原生Edit核对最终文本；真实手机键盘弹出已测，但没有自动操作某个第三方输入法的候选栏。所有输入测试只操作生成的专用画布与窗口，主机诊断PID保护保证目标失焦后拒绝注入。

有效回归包括当前C++ integration70项（含新增操作权限、截断、无效阶段、UTF-8/长度/控制字符、按键范围/通道和音频）、Java互操作13项+integration71项、viewport19项。core88项通过。旧点击坐标测试保留，新版本另跑回归。

失败尝试保留：attempt1自动键盘首次未显示；已加入短延后一次焦点重查和请求代号，防旧点击的查询覆盖新操作。attempt2测试画布在UTF-16高代理字符暂态转换UTF-8时异常，修复测试记录器并保留失败证据；产品不记录文本。attempt3租约测试紧邻两次按下被Windows识别成额外双击，隔开超过系统默认双击时间后复测通过。

