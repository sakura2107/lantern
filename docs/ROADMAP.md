# 分阶段交付与验收

## 阶段 1：当前交付

真实 C++ Windows 主机/CLI、Windows 原生 GUI、共享 C++ 协议的 Android 原生客户端源码、TLS 指纹配对、独立文件页、可恢复双向单文件任务、实际 GDI/JPEG 桌面、点击输入、原始媒体外部读取、只读外部文档打开、C ABI 插件示例、CMake/打包与自动验证。Android 构建状态和实测以 VALIDATION 为准。

2026-10-13 追加：Android 全屏/横竖屏/双指缩放、真实拖拽/电脑双击/输入法，NVIDIA DXGI→NVENC H264→Android MediaCodec，以及独立WASAPI→AudioTrack系统音频短测已落地；Windows GPU 解码、Windows音频播放、音画同步、音频压缩等阶段3项目仍未实现。

该阶段不满足整个产品范围。已实现功能与当前不支持能力要同时显示；目前 CLI capability 查询承担这一部分，UI 的完整能力面板后续补齐。

## 阶段 2：可靠可用的客户端与文件产品

先实现按设备身份/权限存储、会话终止列表、明确的无人值守开关；将 Java 任务循环迁移到共享 C++。统一 task ID/state、取消、暂停、失败与磁盘恢复，所有任务可见；增加目录/批量传输、主机内目录复制、分页 generation、排序和可取消递归搜索、缩略图、冲突选择、缓存上限与回收、单控制者输入租约与掉线释放、剪贴板和快捷键。

验收：两台 Windows 和一台 Android 真机完成配对→无桌面文件浏览→10 GiB 双向传输→中断/主机重启后恢复→源修改失败→缓存用现有办公应用打开；1 万小文件批量取消恢复；逐设备撤销不影响另一台；磁盘满/文件占用不损坏既有原件。存储和队列峰值必须有实测。

## 阶段 3：低延迟硬件桌面与音频

Desktop Duplication/Windows Graphics Capture、多显示器、D3D11 低复制路径、真实硬件 AVC/HEVC 提供者、Android MediaCodec/Surface、Windows GPU 解码；WASAPI 系统音频、独立音频权限、时间戳映射、抖动缓冲、音画同步。界面补全全屏、缩放、横竖屏、分辨率/画质与触控/鼠标模式。保留 GDI/JPEG 作为显式降级。

验收：文档指定设备网络下，1080p60、硬件 encode/decode 确认、p95 端到端延迟<80 ms、10 分钟丢帧<1%、音画偏差≤40 ms；并行文件传输下输入/音频不中断。采集暂停、显示隐藏、隐私屏分别测试。隐私屏和虚拟显示器按实际系统/驱动能力提供，不能用黑色客户端画面代替主机隐私。

## 阶段 4：完整观影与自适应网络

可选媒体包独立发布：容器/轨道探测、客户端解码/HDR/声道/字幕能力矩阵、原始直传→重封装→按需转码决策、外部手机播放器对多音轨/外挂字幕/ASS 字体、速度/进度/连续播放的兼容验证、播放接力。低延迟桌面与观影预缓冲采用不同管线。

引入真实链路容量反馈、跨通道公平预算、QUIC/RTP 期限调度、恢复 ID、网络切换与弱网重连；文件吞吐使用剩余预算。公网、穿透和中继作为可选模块，端到端验证不变。

验收：真实 4K Main10、40/80/100 Mbps 动漫样本、复杂 ASS/字体附件、双音轨、HDR10、外挂字幕；记录首帧、20 次随机 seek、重缓冲、A/V 和降级原因。用真实 Android 温度与降频测量，不用桌面 JPEG 测量替代 4K 解码验证。测试矩阵全部重新运行。
